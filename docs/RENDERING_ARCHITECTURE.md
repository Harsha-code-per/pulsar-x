# PULSAR-X — Real-Time 3D Scientific Visualization Engine Architecture

## 1. Executive Summary & Core Engineering Principle
The **PULSAR-X Real-Time 3D Scientific Visualization Engine** provides a physically grounded, cinematic WebGL2 viewport representing deep-space navigation without GPS. In accordance with the project constitution (`AGENTS.md`), the 3D rendering engine visualizes authoritative simulation telemetry generated by the background Web Worker.

```
+---------------------------+
|  Scientific Web Worker    |  Ground Truth SI Physics (BCRS, Relativistic Delays, IEKF)
+---------------------------+
              | (Throttled Telemetry Packets, Zero-Allocation Buffers)
              v
+---------------------------+
|   TelemetryAdapter        |  Temporal Hermite / Linear Interpolation (60-120 Hz presentation)
+---------------------------+
              | (Discrete Physical Snapshots -> Continuous Visual Transform)
              v
+---------------------------+
| Three.js / R3F Viewport   |  Macro-Scaled Heliocentric Rendering & Floating Origin Rig
+---------------------------+
```

### Inviolable Simulation Integrity Rule
The renderer **never fabricates or spoofs**:
- Spacecraft position or velocity
- Navigation residual errors
- Geometric Dilution of Precision (GDOP / PDOP)
- Covariance uncertainty axes or eigenvalues
- Pulsar pulse phase or active tracking states
- Photon arrival statistics

All visual features are strictly telemetry-driven or explicit pedagogical approximations labeled in code.

## 3. Coordinate Scaling Strategy & Floating Origin

### Physical Scale vs Single-Precision WebGL
Physical coordinates operate in SI meters in the Barycentric Celestial Reference System (BCRS). Raw heliocentric coordinates ($1\text{ AU} \approx 1.496 \times 10^{11}\text{ m}$) exceed the 24-bit mantissa precision of WebGL single-precision floats, leading to vertex jittering if unmanaged.

### Scale Invariants (`src/rendering/coordinates/scaling.ts`)
- **Macro Heliocentric Scale:**
  $$\text{Render Units} = \text{SI Meters} \times \frac{100.0}{1.495978707 \times 10^{11}}$$
  $1.0\text{ AU} \equiv 100.0\text{ render units}$.
- **Celestial Horizon Sphere:**
  Pulsars are located light-years away. In the solar system frame, pulsar direction vectors are projected onto a celestial horizon sphere of radius $R = 250.0\text{ render units}$:
  $$\mathbf{r}_{\text{render}} = \frac{\mathbf{u}}{\|\mathbf{u}\|} \times 250.0$$
- **Visual Error Magnification Mode:**
  Because physical navigation error ($\sim 500\text{ m} = 3.34 \times 10^{-7}\text{ render units}$) is sub-pixel at $100\text{ units}/AU$, an explicit error magnification factor ($1\times, 10\times, 100\times, 1000\times$) is provided. The HUD and overlay explicitly label this: `"ERROR VECTOR — VISUAL SCALE ×N"`.
- **Floating Origin Capability:**
  The `scientificToRenderPosition(pos, originOffset)` function accepts an optional local origin in physical meters. When close-up spacecraft inspection or docking is active, the spacecraft position serves as the floating origin, avoiding floating-point precision loss.

## 4. Telemetry Adapter & State Interpolation

### Discrete Worker Cadence -> Continuous 120 Hz Render Loop
The Web Worker broadcasts `WorkerTelemetryFrame` packets at $\sim 20\text{ Hz}$. The rendering loop executes at the native display refresh rate ($60\text{ Hz} - 120\text{ Hz}$).

The `TelemetryAdapter` maintains:
1. `prevFrame`: Prior authoritative telemetry snapshot
2. `currentFrame`: Most recent authoritative telemetry snapshot
3. `getVisualState(alpha)`: Performs linear/spherical interpolation between frames:
   $$\mathbf{r}(t) = \mathbf{r}_{\text{prev}} + \alpha (\mathbf{r}_{\text{curr}} - \mathbf{r}_{\text{prev}}), \quad \alpha \in [0.0, 1.0]$$

Interpolation is computed in SI meters before conversion to render coordinates to maintain physical geometry. Scientific values are never modified by the adapter.

## 5. Camera Architecture & CameraController

### CameraController Abstraction (`src/rendering/cameras/CameraController.ts`)
The `CameraController` class provides an extensible interface that decouples user orbit interaction from future scripted Director sequences:

```ts
class CameraController {
  setTarget(x: number, y: number, z: number): void;
  setPosition(x: number, y: number, z: number): void;
  setFOV(fov: number): void;
  lookAt(x: number, y: number, z: number): void;
  transitionTo(config: CameraTargetConfig): void;
  enableUserControl(): void;
  disableUserControl(): void;
  canUserControl(): boolean;
  isTransitioning(): boolean;
  update(delta_s: number, camera?: THREE.Camera, controls?: OrbitControlsImpl): void;
}
```

### Camera Rig Modes
- **`FREE`:** User-controlled OrbitControls with damping.
- **`SPACECRAFT_FOLLOW`:** Smoothly tracks the spacecraft heading and position at close range.
- **`PULSAR_FOCUS`:** Frames the active pulsar beacon against the spacecraft.
- **`SYSTEM_OVERVIEW`:** Wide-angle view showing Sun, Earth, and inner solar system.
- **`GEOMETRY_OVERVIEW`:** 4D tetrahedral constellation geometry framing.

Transitions between modes utilize a cubic ease-in-out curve ($S(t) = 4t^3$ or $1 - \frac{(-2t+2)^3}{2}$) with smooth FOV and lookAt dampening.

## 6. Procedural Starfield & Celestial Environment

### Plausible Astronomical Distribution
Rather than a uniform random sphere, `Starfield.tsx` generates 25,000 stars (in HIGH quality) using a deterministic Mulberry32 PRNG (seed `421937`):
- **Galactic Concentration:** 65% of stars are concentrated within the galactic disk, inclined by $63^\circ$ relative to the ecliptic plane.
- **Scale Height Falloff:** Exponential Laplace distribution along galactic latitude $b$.
- **Stellar Classification:** Colors reflect spectral classes:
  - O/B/A hot stars (blue-white)
  - F/G solar analogs (subtle warm white)
  - K stars (amber)
  - M red dwarfs (pale reddish-orange)
- **Magnitude Distribution:** Point sizes and brightness follow a power-law distribution.
- **Single GPU Draw Call:** All stars are rendered in one `THREE.Points` instance via interleaved `BufferGeometry`.

### Deep Space Cosmic Background
An inverted procedural sky sphere with GLSL dust gradient provides faint galactic glow along the galactic plane without distracting gaming-style nebulas.

## 7. Planetary & Solar Models

### Sun (`SunNode.tsx`)
- **Core:** Procedural limb-darkening shader: $I(\mu) = I_0(1 - u(1 - \mu))$ creating depth towards the solar limb.
- **Corona:** Translucent additive outer shell with animated flare rotation.
- **Lighting:** Omnidirectional `PointLight` at $[0, 0, 0]$ with zero decay, illuminating planets and spacecraft radially outward, complemented by directional key lighting.

### Earth (`EarthNode.tsx`)
- **Globe:** Self-contained WebGL shader (zero external image URLs) computing:
  - High-contrast day/night terminator
  - Ocean depth reflectance vs continental earth tones
  - Night-side city lights
  - Rayleigh-inspired atmospheric rim scattering (Fresnel exponent 3.2)
- **Cloud Layer:** Concentric sphere at radius $r = 2.24$ with procedural cloud swirls and independent drift rotation ($+30\%$ relative to surface).

## 9. Pulsar Visual System

### Hierarchical Pulsar Node
Each pulsar in `INITIAL_PULSAR_CATALOG` is modeled as a reusable `PulsarNode`:
1. **Neutron Star Core:** Procedural GLSL shader with domain-warped sinusoidal lattice crust, rapid rotation, and polar magnetic emission caps.
2. **Magnetic Axis:** Slender luminous needle tilted along the magnetic inclination angle ($\sim 30^\circ$).
3. **Synchrotron Beams:** Dual opposing emission cones with volumetric gradient shader (additive blending, smooth longitudinal attenuation).
4. **Pulse Wave:** Expanding spherical wavefront shell triggered at peak phase $\phi \approx 0$ and dissipating with radius.
5. **Halo:** Magnetospheric Fresnel glow.
6. **Signal Link:** World-space beacon marker and target glyph.

### Simulation Phase Synchronization
The rotational spin and pulse wave are driven directly by the scientific timing model:
$$\phi(t) = \text{wrapPhaseToCycle}\left(\Phi_0 + f_0 \Delta t + \frac{1}{2} f_1 \Delta t^2\right)$$
When a pulsar is dropped or inactive according to the worker's `activePulsarMask`, its synchrotron beams vanish, its core dims, and its sightline line collapses.

## 10. Covariance Uncertainty Ellipsoid

### Mathematical Formulation
The uncertainty ellipsoid is transformed from the $3 \times 3$ position covariance matrix:
$$\mathbf{P}_{\text{pos}} = \begin{bmatrix} \sigma_{xx}^2 & \sigma_{xy} & \sigma_{xz} \\ \sigma_{yx} & \sigma_{yy}^2 & \sigma_{yz} \\ \sigma_{zx} & \sigma_{zy} & \sigma_{zz}^2 \end{bmatrix}$$
Through Jacobi eigenvalue decomposition:
$$\mathbf{P}_{\text{pos}} \mathbf{v}_i = \lambda_i \mathbf{v}_i, \quad \sigma_i = \sqrt{\lambda_i}$$

The ellipsoid is rendered around the estimated spacecraft position:
- **1σ:** Contains 19.9% 3D probability mass.
- **2σ:** Contains 73.9% 3D probability mass.
- **3σ:** Contains 97.1% 3D probability mass.

### State-Aware Color Treatment
- **`LOCKED`:** Restrained aerospace cyan (`#00f5ff`)
- **`DEGRADED`:** Navigation warning amber (`#ffb703`)
- **`CRITICAL` / `SINGULAR`:** Critical failure rose (`#ff3366`)

## 11. Trajectory System

The trajectory trail samples physical spacecraft state every $0.1\text{ s}$ of simulation time:
- **True Trajectory:** Solid cyan line.
- **Estimated Trajectory:** Translucent amber line.
- **FIFO Buffer Shifting:** When the buffer reaches `MAX_TRAJECTORY_POINTS = 500`, typed array memory is shifted via `tArr.copyWithin(0, 3)`. This maintains chronological ordering and guarantees that no wrap-around line artifacts or zig-zag seams appear across space.

## 12. Render Quality Tiers & Performance Discipline

| Quality Tier | Starfield Count | Max DPR Clamp | Bloom Enabled | Vignette | Antialiasing | Film Grain |
|:---|:---:|:---:|:---:|:---:|:---:|:---:|
| **LOW** | 6,000 | 1.0 | No | Yes | Off | Off |
| **MEDIUM** | 14,000 | 1.5 | Yes (0.5) | Yes | 4x MSAA | Off |
| **HIGH** (Default) | 25,000 | 2.0 | Yes (0.8) | Yes | 4x MSAA | 0.03 |
| **CINEMATIC** | 35,000 | 2.0 | Yes (1.1) | Yes | 4x MSAA | 0.05 |

### Performance Safeguards
1. **DPR Clamping:** Device pixel ratio is clamped to $\le 2.0$ across all tiers to prevent thermal throttling on 4K/retina displays.
2. **Zero Heap Allocation in Hot Loops:** No vectors, matrices, or materials are allocated inside `useFrame`.
3. **Instanced Geometry:** Repeated stars and beacons use BufferGeometry with unified draw calls.
4. **Draw Call Budget:** Total draw calls remain strictly under 50 per frame.

## 13. Browser Fallback & Diagnostics

1. **WebGL Error Boundary (`WebGLErrorBoundary`):**
   Catches WebGL context loss or shader compilation errors gracefully, presenting an aerospace failure diagnostics screen with a single-click subsystem recovery button.
2. **Developer Diagnostics Overlay:**
   Displays live WebGL draw calls, triangle counts, engine FPS, simulation time, incoming telemetry rate, 4D GDOP, position error, and active pulsar mask.
3. **Accessibility:**
   Automatically detects `prefers-reduced-motion: reduce`. When active, camera pan speeds and animations are throttled to prevent disorientation.
