## 2. Director Architecture & Core Domains

### 2.1 State Machine (`DirectorState.ts`)
- Implements an 8-state finite state machine (`IDLE`, `LOADING`, `READY`, `PLAYING`, `PAUSED`, `SEEKING`, `COMPLETED`, `ERROR`).
- Enforces strict transition validation; illegal transitions throw structured `DirectorStateError` instances.
- Zero state desynchronization: all state changes publish to `useCinematicStore`.

### 2.2 Triple-Clock Decoupling (`CinematicClock.ts`)
- **Wall Clock:** Real-time performance monitor timestamp (never fed to scientific equations).
- **Simulation Clock:** Authoritative coordinate time ($t_{\text{sim}}$) generated by the simulation Web Worker.
- **Cinematic Playhead:** Normalized sequence time ($t_{\text{playhead}}$), advancing at user/director-defined rates ($0.5\times\text{–}5.0\times$).

### 2.3 Event Bus & Trigger Priority (`CinematicEventBus.ts` & `triggers/types.ts`)
- Bridges Worker event notifications (`WORKER_EVENT`) into the director domain:
  - `SIMULATION_READY`, `GNSS_DEGRADED`, `GNSS_LOST`, `GROUND_LINK_LOST`
  - `PULSAR_ACQUIRED`, `PULSAR_LOST`, `OBSERVATION_AVAILABLE`
  - `NAVIGATION_DEGRADED`, `NAVIGATION_RECOVERED`, `NAVIGATION_LOCKED`
  - `SOLAR_OCCULTATION`, `MISSION_ARRIVAL`, `CINEMATIC_COMPLETE`
- Priority resolution guarantees physical fidelity:
  $$\text{EVENT\_TRIGGER} (100) > \text{TELEMETRY\_TRIGGER} (50) > \text{PLAYHEAD\_TRIGGER} (10)$$

## 8. Differences from Original Cinematic Design

1. **Solver Terminology:** The active runtime solver is an **Iterative Batch Weighted Least Squares** estimator with continuous **RK4 Dead Reckoning** and orbital smoothing per `docs/NAVIGATION_RUNTIME_AUDIT.md`. Early references to "IEKF" or "Kalman Filter" were updated across all captions, badges, and readouts to maintain strict scientific honesty.
2. **Modular Scene Files:** The 18 scenes were authored as separate, strongly-typed modules in `src/cinematic/scenes/` rather than a single monolithic configuration file.
3. **Event-Driven Triggers:** Transitions leverage genuine simulation Web Worker events (`WORKER_EVENT`) with priority over elapsed playhead timers.
